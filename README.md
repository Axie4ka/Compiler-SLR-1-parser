# Компилятор логического языка (SLR(1))

Учебный компилятор небольшого языка с логическими переменными (вариант 8).
Курсовая работа, группа 24ВП2, Савчук Д., Савчук М.

Программа читает исходный текст, проводит лексический, синтаксический (восходящий SLR(1)-разбор)
и семантический анализ, строит постфиксную запись (ПОЛИЗ) и генерирует
ассемблерный код x86 (16 бит, DOS, MASM). Готовую программу можно собрать и запустить в DOSBox.

## Язык

Единственный тип данных — `LOGICAL` (значения `0` и `1`).

```
VAR A, B, C : LOGICAL;
BEGIN
    READ(A, C);
    IF A .EQU. 1 THEN
        B = 0;
    ELSE
        B = .NOT. (( A .OR. 1 ) .AND. .NOT. A);
    END_IF;
    WRITE(B, C);
END
```

- Идентификаторы: только латинские буквы, не длиннее 9 символов, регистр различается.
- Ключевые слова: `VAR`, `BEGIN`, `END`, `LOGICAL`, `READ`, `WRITE`, `IF`, `THEN`, `ELSE`, `END_IF`
  (пишутся заглавными буквами).
- Операции по убыванию старшинства: `.NOT.`, `.AND.`, `.OR.`, `.EQU.`; скобки `( )`.
- Условный оператор содержит обе ветки (`THEN` и `ELSE`), в ветках — только присваивания.

## Грамматика

Грамматика задана в `Parsing/Grammar.cs` (метод `CreateDefault`). Терминалы — ключевые слова,
знаки и два обобщённых символа: `id` (идентификатор) и `const` (константа `0` или `1`).
Что именно считать идентификатором и константой, решает лексер, поэтому правил для букв и цифр
в грамматике нет.

```
Программа            -> ОбъявлениеПеременных ОписаниеВычислений

ОбъявлениеПеременных -> VAR СписокПеременных : LOGICAL ;
СписокПеременных     -> id
                      | id , СписокПеременных

ОписаниеВычислений   -> BEGIN СписокОператоров END
СписокОператоров     -> Оператор
                      | СписокОператоров Оператор
Оператор             -> Присваивание | Ввод | Вывод | УсловныйОператор

Присваивание         -> id = Выражение ;
Ввод                 -> READ ( СписокПеременных ) ;
Вывод                -> WRITE ( СписокПеременных ) ;
УсловныйОператор     -> IF Выражение THEN СписокПрисваиваний
                        ELSE СписокПрисваиваний END_IF ;
СписокПрисваиваний   -> Присваивание
                      | Присваивание СписокПрисваиваний

Выражение            -> Выражение .EQU. Дизъюнкция | Дизъюнкция
Дизъюнкция           -> Дизъюнкция .OR. Конъюнкция | Конъюнкция
Конъюнкция           -> Конъюнкция .AND. УнарноеВыражение | УнарноеВыражение
УнарноеВыражение     -> .NOT. УнарноеВыражение | Подвыражение
Подвыражение         -> ( Выражение ) | Операнд
Операнд              -> id | const
```

- Старшинство операций заложено в самой грамматике: чем ниже правило, тем выше приоритет
  (`.EQU.` → `.OR.` → `.AND.` → `.NOT.`). `.EQU.`, `.OR.` и `.AND.` левоассоциативны.
- Пустых правил нет.
- Перед построением таблицы грамматика дополняется правилом `S' -> Программа`.
  Всего получается 30 правил с учётом всех альтернатив.
- Таблица SLR(1) строится автоматически. Конфликты, если они появятся, программа выводит
  в разделе «Конфликты таблицы разбора»: перенос выбирается вместо свёртки, а из двух свёрток
  берётся правило с меньшим номером.

## Этапы работы

| Этап | Класс | Что делает |
| ---- | ----- | ---------- |
| Лексический анализ | `Lexing/Lexer.cs` | Таблицы лексем, идентификаторов и констант; останавливается на первой ошибке |
| Синтаксический анализ | `Parsing/LrTableBuilder.cs`, `LrParser.cs` | Строит SLR(1)-таблицу, разбирает снизу вверх, выводит протокол разбора и дерево |
| Семантический анализ | `Semantics/SemanticAnalyzer.cs` | Повторное объявление, необъявленные переменные, использование до присваивания, предупреждение о неиспользуемых |
| Постфиксная запись | `Generation/PostfixGenerator.cs` | Строит ПОЛИЗ с метками и переходами `УПЛ` / `БП` |
| Генерация кода | `Generation/CodeGenerator.cs` | Ассемблер x86 16 бит по ПОЛИЗ (стековая машина, значения в `AL`) |
| Сборка и запуск | `Generation/DosRunner.cs` | `ml` → `link16` → DOSBox |

## Требования

- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- Для сборки и запуска сгенерированной программы (необязательно):
  MASM32 (`ml.exe`, `link16.exe`) и DOSBox 0.74.

## Сборка и запуск

```
dotnet build
dotnet run --project Course_work_Savchuk_Savchuk
```

Без аргументов программа предлагает выбрать источник текста: ввод с клавиатуры или файл
(пустой путь — `program.txt` рядом с программой).

```
dotnet run --project Course_work_Savchuk_Savchuk -- путь\к\файлу.txt
dotnet run --project Course_work_Savchuk_Savchuk -- путь\к\файлу.txt /run
```

- Путь к файлу в аргументе — читать исходный текст из него.
- Ключ `/run` — после генерации сразу собрать программу и запустить её в DOSBox.
  В интерактивном режиме программа сама спросит, запускать ли сборку.

Ассемблерный код сохраняется рядом с исходным файлом под тем же именем с расширением `.asm`.
При вводе с клавиатуры файл называется `program.asm` и лежит рядом с программой.

### Пути к инструментам

Пути к `ml`, `link16` и DOSBox задаются в файле `tools.txt`, который копируется
в папку с программой при сборке:

```
ml     = C:\masm32\bin\ml.exe
link16 = C:\masm32\bin\link16.exe
dosbox = C:\Program Files (x86)\DOSBox-0.74-3\DOSBox.exe
```

Строки, начинающиеся с `;`, — комментарии. Если файла нет, используются пути по умолчанию.

## Тесты

```
dotnet test
```

Тесты (xUnit) покрывают лексер, грамматику, построение таблицы, разбор, семантику,
постфиксную запись, генерацию кода и работу `DosRunner`. Сами `ml`, `link16` и DOSBox в тестах
не запускаются.
